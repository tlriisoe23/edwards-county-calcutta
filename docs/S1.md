## Pre-implementation audit

Source evidence: `app/globals.css`, `app/refinements.css`, `app/rules.tsx`, `app/operator.tsx`, `app/auction.tsx`, `lib/model.ts`, `lib/store.ts`, `app/api/admin/route.ts`.

- Global shadcn-compatible variables already own backgrounds, foregrounds, primary/secondary, cards/popovers, borders, destructive and ring. Numerous component rules bypass them with hard-coded cream, white, green and gold shades across both stylesheets. There is no functional event theme selector or dark preset.
- Operator and public/TV reuse Block, Stats and PoolCards. TV changes layout/type scale, not the palette. The dark green current-lot block has separate gold bid, pale text, header and paused colors; preserve that hierarchy through explicit semantic roles.
- State badges (sold/on-block/unsold/paid/overpaid), readiness, phase, connection, money and notices each have component color rules. Labels/icons already carry meaning independently of color.
- Flight colors are event-owned identity accents (editable in the existing flight dialog), used as border markers beside flight names. Preserve their persisted values and text labels; they must never become text/background contrast dependencies or a new theme editor.
- Focus combines browser defaults with primitive ring utilities; use a consistent opaque focus outline including disclosures. C1 reported `.roster th`, `.flight-setting small`, `.empty-state p` contrast problems; route these through readable secondary text.
- Dialogs/selects portal outside the page; the event theme must reach the document root, not only the main element. Print/QR need fixed paper/ink colors.
- `event.settings` JSON is authoritative; reads normalize settings, event_update validates/saves them under existing revision/audit controls, and the public API allowlists display fields. A single shared theme can use these owners with no schema migration, localStorage or new configuration service.

## Approved decisions and setting classification

| Scope | Outcome | Protected behavior / validation |
|---|---|---|
| Themes | Classic ECGC (default), High Contrast, Dark Event, Light Event; semantic token presets shared by operator/public/TV | Persistence, invalid/missing fallback, portals, colors, visibility, state unchanged |
| Advanced | Existing rules tab with native disclosure; C1 shortcut opens and focuses it | Original tab values, keyboard/focus, roles, saved draft/revision behavior |

| Settings | Placement and reason |
|---|---|
| Event name/course/dates, description/rules, currency | Normal: operators need to verify the event and denomination before opening |
| Minimum bid/increment, pool configuration, house deduction | Normal: core event decisions, even though changing money rules during an auction is risky |
| Flights, payout ladders, status controls | Normal: necessary setup/readiness and existing confirmations stay available |
| Theme preset | Normal in Display & sharing: quick shared readability choice, independently saved to avoid submitting unrelated rule drafts |
| Bidder tracking, auto-advance, opening/increment button lists | Advanced: specialist operator preferences with useful saved/current summaries |
| Buyback mode/suggestion/ownership/price/deadline | Advanced: optional private agreements, default Off; show current mode in the closed summary |
| Public visibility flags | Advanced display group: infrequent audience/privacy configuration; existing flags and projection remain authoritative |
| Pool/share/currency changes, auto-advance/tracking, visibility, lifecycle/reset/access | Potentially disruptive: explain consequences near affected controls; preserve existing validation/confirmation/permission boundaries. Access stays owner-only in C1 Tools; reset stays where it is |

Use one shared theme: no demonstrated need for independent operator/TV choices, and a single saved event selection prevents mismatched displays. No rotation, window-launch work, business rules, schema migrations, production data or leaderboard changes.
